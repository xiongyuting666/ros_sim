# 测试用例文档

## 测试对象
ros_sim 简易ROS发布订阅模拟器

## 测试环境
- 操作系统：Windows
- 编译器：MinGW-w64 g++，C++11
- 运行方式：CMD

## 测试说明
程序按 8 个场景依次执行，每个场景独立 try-catch，异常场景捕获后程序继续运行。
预期结果：正常流程打印 INFO 日志；异常场景输出 ERROR 日志且程序不崩溃；全部日志同步写入 log.txt。

| 编号 | 测试类型 | 测试内容 | 预期结果 | 实际结果 |
| ---- | ---- | ---- | ---- | ---- |
| 1 | 正常功能 | 1个发布者、2个订阅者绑定同一话题 /chatter，发布消息 | 两个订阅者都收到消息，控制台输出 INFO 发布、接收日志，log.txt 同步记录 | 通过：sub1、sub2 均输出 [Receive] 日志，内容与时间戳正确 |
| 2 | 正常功能 | 同一话题 1 个发布者、多个订阅者，发布一条消息 | 所有订阅者都收到该消息，日志正常打印 | 通过：场景1已覆盖，sub1/sub2 同时收到同一条消息 |
| 3 | 异常测试 | 注册节点，节点名称为空 | 抛出 NodeException，输出 ERROR 日志，程序继续运行 | 通过：输出"节点异常：ERROR:节点名称不能为空"，后续场景正常执行 |
| 4 | 异常测试 | 重复注册同一订阅者 | 抛出 NodeException，输出 ERROR 日志，程序继续运行 | 通过：输出"节点异常：ERROR:订阅者已注册该话题，重复注册" |
| 5 | 异常测试 | 话题名称为空，注册订阅者 | 抛出 TopicException，输出 ERROR 日志，程序继续运行 | 通过：输出"话题异常：ERROR:话题名称不能为空" |
| 6 | 异常测试 | 向没有订阅者的话题 /lonely 发布消息 | 抛出 TopicException，输出 ERROR 日志，程序继续运行 | 通过：输出"话题异常：ERROR:向不存在订阅者的话题转发消息:/lonely" |
| 7 | 异常测试 | 发布内容为空的消息 | 抛出 MessageException，输出 ERROR 日志，程序继续运行 | 通过：输出"消息异常：ERROR:消息内容不能为空" |
| 8 | 日志测试 | 正常运行、WARN 触发、ERROR 触发 | INFO/WARN/ERROR 分级输出，格式统一，全部内容写入 log.txt | 通过：格式为 [时间] [等级] 内容，log.txt 共写入 70 行，与控制台一致 |
| 9 | 扩展功能 | 使用 SensorMessage（温度26.5、湿度60.2）发布 | 消息携带温度、湿度、时间戳，订阅端正常解析打印 | 通过：订阅端收到 [SensorMessage] temperature:26.50C humidity:60.20% 并附时间戳 |
| 10 | 设计验证 | 两次调用 RosCore::getInstance() | 返回同一个实例地址 | 通过：单例验证通过，两次获取到同一个实例 |
| 11 | 设计验证 | 尝试直接实例化 Node / 修改 Message 内部数据 | 抽象类不可实例化；Message 无 const 以外写接口 | 通过：Node 纯虚函数使其不可实例化；Message 只提供 const 读取接口 |

## 测试总结
本次测试覆盖基础通信功能、多订阅广播、三类异常场景、日志持久化、传感器扩展消息、单例与抽象类设计验证。
所有异常场景均可被捕获，程序不崩溃并继续执行后续场景，符合设计要求。
