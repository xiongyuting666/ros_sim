# 结构化测试用例

## 测试对象
ros_sim 简易 ROS 发布订阅模拟器（含服务通信、动态节点、异常与日志）

## 测试环境
- 操作系统：Windows
- 编译器：MinGW-w64 g++ 16.2.0（C++11）
- 编译命令：`g++ -std=c++11 -Wall -Wextra main.cpp RosCore.cpp Publisher.cpp Subscriber.cpp -o ros_sim.exe`
- 运行方式：CMD 下执行 `ros_sim.exe`
- 判定方式：控制台输出 + 运行目录 `log.txt` 内容比对

## 测试设计说明
程序内置 11 个场景，每个场景由 `runCase()` 独立 try-catch，异常场景捕获后程序继续执行下一场景。
覆盖类型：正常场景（1-3、5）、边界场景（9）、异常场景（4、6-8、10）、设计验证（11）。

## 用例表

| 编号 | 类型 | 前置条件 | 测试步骤 | 预期结果 | 实际结果 |
| --- | --- | --- | --- | --- | --- |
| TC-01 | 正常 | 无 | 创建 pub1、pub2 与 sub1、sub2，绑定话题 /chatter；先订阅后发布；pub1、pub2 各发一条消息 | 两个订阅者分别收到两条消息，日志含内容与时间戳，发布者不等响应即可继续 | 通过：sub1/sub2 各输出 2 条 [Receive]，内容分别为 hello from pub1 / hello from pub2 |
| TC-02 | 正常 | 无 | 构造 SensorMessage(26.5, 60.2) 并通过 /sensor 发布 | 订阅端收到含温度 26.50、湿度 60.20 与时间戳的消息 | 通过：输出 `[SensorMessage] temperature:26.50C humidity:60.20% time:2026-11-16 20:43:58` |
| TC-03 | 正常 | 无 | 注册 echo_service，客户端按该服务名发起 req("查询当前温度") | 客户端阻塞等待，收到服务端处理后返回的响应 | 通过：客户端输出"客户端收到响应:服务端已处理请求 -> 查询当前温度" |
| TC-04 | 异常 | 场景3已注册 echo_service | 客户端调用不存在的服务名 not_exist_service | 抛出 ServiceException，输出 ERROR 日志，程序继续 | 通过：`服务异常：ERROR:调用了不存在的服务:not_exist_service` |
| TC-05 | 正常/动态 | 无 | 运行时注册 dyn_pub(/dynamic) → 运行时注册 dyn_sub → 发布 → 注销 dyn_sub → 再发布 | 首次发布订阅者收到；注销后再发布抛出 TopicException | 通过：首次收到消息，注销后输出 `话题异常：ERROR:向不存在订阅者的话题转发消息:/dynamic` |
| TC-06 | 异常 | 无 | 以空话题名 "" 构造 Subscriber 并 init | 抛出 TopicException，输出 ERROR，程序继续 | 通过：`话题异常：ERROR:话题名称不能为空` |
| TC-07 | 异常 | 无 | 以空节点名 "" 构造 Subscriber 并 init | 抛出 NodeException，输出 ERROR，程序继续 | 通过：`节点异常：ERROR:节点名称不能为空` |
| TC-08 | 异常 | 无 | 同一 Subscriber 连续两次 init（重复注册） | 第二次抛出 NodeException，输出 ERROR，程序继续 | 通过：`节点异常：ERROR:订阅者已注册该话题，重复注册` |
| TC-09 | 边界/异常 | 话题 /empty 下已有订阅者 | 发布内容为空字符串的 Message | 抛出 MessageException，输出 ERROR，程序继续 | 通过：`消息异常：ERROR:消息内容不能为空` |
| TC-10 | 异常 | 无 | 仅在 /lonely 注册发布者，不注册任何订阅者，直接发布 | 抛出 TopicException，输出 ERROR，程序继续 | 通过：`话题异常：ERROR:向不存在订阅者的话题转发消息:/lonely` |
| TC-11 | 设计验证 | 无 | 两次调用 RosCore::getInstance() 比较地址 | 两次返回同一实例地址 | 通过：`单例验证通过：两次获取到同一个RosCore实例，地址相同` |
| TC-12 | 日志 | 以上场景全部执行 | 检查运行目录 log.txt | 全部日志写入文件，格式为 `[时间] [等级] 内容`，与控制台一致 | 通过：log.txt 共 104 行，INFO/WARN/ERROR 分级正确，与控制台输出一致 |
| TC-13 | 编译 | 无 | 使用 -Wall -Wextra 编译全部源文件 | 零 error、零 warning | 通过：exit=0，无任何警告 |

## 覆盖情况统计
- 正常场景：TC-01、02、03、05（前半）
- 边界场景：TC-09
- 异常场景：TC-04、TC-05（后半）、06、07、08、10
- 设计验证：TC-11
- 日志与编译：TC-12、TC-13
- 异常类型覆盖：NodeException、TopicException、MessageException、ServiceException 四类全覆盖

## 测试结论
全部用例执行通过。异常场景均被捕获并输出语义清晰的 ERROR 日志，程序未崩溃且后续场景正常执行，符合需求中"程序禁止崩溃"的要求。
