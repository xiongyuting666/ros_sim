# 需求文档

## 1. 项目概述
本项目为 C++ 课程大作业，要求模拟 ROS（Robot Operating System）最核心的通信机制——**发布 / 订阅（Publish-Subscribe）**模型，并在此基础上补充服务通信、异常处理与日志持久化能力，实现一个可运行、可扩展的简易消息仿真系统。

## 2. 角色与使用场景
| 角色 | 说明 |
| --- | --- |
| 开发者 | 编写节点、消息、核心调度模块，完成系统功能 |
| 使用者 | 通过命令行运行程序，观察节点注册、消息发布、接收、异常处理等完整流程 |
| 评阅者 | 依据本仓库提交的代码与五类文档进行评分 |

## 3. 功能需求

### 3.1 基础功能（必做）
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F-01 | 节点基类 Node | 所有节点的抽象父类，封装唯一的节点名称并提供名称只读方法；定义初始化接口与关闭接口，由子类实现并输出对应的初始化、关闭日志 |
| F-02 | 发布者 Publisher | 继承 Node；扩展话题名称属性并提供只读接口；初始化时输出日志并向 ROS 核心注册自身；关闭时输出关闭日志；发布功能需模拟接收传感器字符串信息、创建消息对象、输出发布日志并转发到核心对应话题 |
| F-03 | 订阅者 Subscriber | 继承 Node；扩展话题名称属性并提供只读接口；初始化时输出日志并向核心注册；关闭时输出日志；接收消息后输出包含**消息内容与时间戳**的接收日志 |
| F-04 | 消息类 Message | 封装字符串类型消息内容，自动生成 `YYYY-MM-DD HH:MM:SS` 格式时间戳，只提供读取消息内容与时间戳的公有接口，保证封装性与访问可控性 |
| F-05 | ROS 核心模块 | 采用单例模式保证全局唯一实例；维护"话题-发布者""话题-订阅者"两类映射关系；提供发布者、订阅者的注册方法；消息转发需将指定话题的 Message 推送给该话题下所有订阅者；提供统一关闭方法，遍历所有节点执行关闭 |

### 3.2 系统功能需求
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| F-06 | 多发布者、多订阅者 | 系统需支持多个发布者、多个订阅者节点的创建及其映射关系，并输出初始化日志 |
| F-07 | 异步通信语义 | 发布者连续发布消息，发布过程无需等待订阅者响应，发布接口无返回值、不阻塞等待响应 |
| F-08 | 全生命周期 | 所有节点按"初始化 → 消息交互 → 关闭"流程完整运行 |
| F-09 | 异常不允许崩溃 | 面对空节点名、重复节点注册、空消息发布、不存在话题转发等非法输入或操作，程序禁止崩溃，需抛出语义清晰的异常信息 |

### 3.3 加分功能（选做，本次全部实现）
| 编号 | 需求 | 实现情况 |
| --- | --- | --- |
| S-01 | 自定义消息类型 | 已实现 SensorMessage，包含温度、湿度、时间戳 |
| S-02 | 服务 / 客户端同步请求-响应 | 已实现 Service 服务端、ServiceClient 客户端与 RosCore 的服务注册与调用 |
| S-03 | 运行时动态添加或删除节点 | 已实现运行时注册 / 注销订阅者、发布者，并通过实际场景演示 |
| S-04 | 消息收发日志持久化 | 全部日志写入运行目录下 log.txt |
| S-05 | 自定义异常类 | 已实现 NodeException、TopicException、MessageException，并额外实现 ServiceException |
| S-06 | 全局异常捕获 | main 中统一 runCase 捕获，单场景异常不影响后续场景 |
| S-07 | 异常日志分级 | INFO / WARN / ERROR 三级，同时输出控制台与文件 |

## 4. 非功能需求
| 编号 | 需求 | 说明 |
| --- | --- | --- |
| N-01 | 编码规范 | 遵循严格 C++ 编码习惯：头文件保护宏、类成员私有化、const 只读接口、初始化列表 |
| N-02 | 文档完整性 | 提交需求文档、架构设计文档、技术文档、用户手册、结构化测试用例 |
| N-03 | 可测试性 | 测试用例覆盖正常场景、边界场景、异常场景 |
| N-04 | 可维护性 | 模块职责单一，日志分级，异常分类明确 |
| N-05 | 增量开发 | 使用 Git 管理，功能或缺陷修复分次提交，禁止一次性提交全部代码 |

## 5. 约束与假设
1. 运行环境为 Windows，编译器为 MinGW-w64 g++（C++11 及以上）。
2. 不依赖任何第三方库，仅使用标准 C++ 库。
3. 本系统为单进程仿真，不做真实网络通信；"异步"体现为发布接口不等待订阅者返回，而非多线程并行。
4. 节点对象在演示程序中由堆分配创建，长时间运行场景可进一步改为 RAII 管理。

## 6. 验收标准
1. 执行编译命令零错误、零警告，生成可执行文件。
2. 运行后依次输出 11 个场景日志，正常场景功能正确，异常场景均被捕获且程序不崩溃。
3. 运行目录生成 log.txt，内容与控制台一致。
4. 五类文档齐全且与代码实现一致。
